## 1. Architecture & Folder Structure

**Current state.** The top-level structure is idiomatic for App Router: role pages/layouts under `app/`, mutations in `actions/`, role/shared UI in `components/`, domain/infrastructure code in `lib/`, and Prisma schema/migrations under `prisma/`. Pages are server components by default; `components/` has no direct Prisma imports. The route proxy and DB-backed `requireRole` layer provide defense in depth.

The primary weakness is that the stated boundary (`app/**` -> `lib/queries/**`) is not actually enforced: 25 of 40 page files import `@/lib/prisma`. Reads also remain exported as Server Actions, and the Facilities shell has drifted from the proxy and action permissions.

### Where and How to Improve

- **High — enforce the query boundary.** Move page-level reads into domain modules under `lib/queries/`; start with user directories, role dashboards, ad-hoc pages, and Facilities profile approvals. Add ESLint restrictions preventing Prisma imports from page/layout files and components after existing consumers have been migrated. Examples: [app/operations/dashboard/page.tsx](app/operations/dashboard/page.tsx), [app/facilities/route-setting/page.tsx](app/facilities/route-setting/page.tsx), and [app/facilities/profile-approvals/page.tsx](app/facilities/profile-approvals/page.tsx).
- **High — reconcile Facilities authorization.** `proxy.ts` explicitly allows Super Admin into `/facilities`, and many child pages/actions allow `[FACILITIES, SUPER_ADMIN]`, but [app/facilities/layout.tsx](app/facilities/layout.tsx) currently requires only `FACILITIES`. Super Admin requests pass the proxy and then fail at the layout. Define one shared role policy and use it consistently in proxy, layouts, and actions.
- **Medium — remove the dead navigation route.** The Facilities sidebar links to `/facilities/weekly-export`, but there is no page at that path; the export was moved into Route Planning. Remove the stale link or restore a supported route. Location: [app/facilities/layout.tsx](app/facilities/layout.tsx).
- **Medium — move read APIs out of Server Actions.** Protected `getWeekRouteOverview`, `getGeneratedRouteDetails`, `getRoutePlanDetail`, `getRouteLearningStats`, `getRouteMemoryDiagnostic`, and `getVehicleShiftPins` are used as data loaders. Move server-component reads to `lib/queries`; use bounded, authenticated route handlers only where client refresh is required. Do not describe these as unauthenticated: they currently have role guards.
- **Medium — reduce component and action size.** First-party modules still include [lib/routing/algorithms.ts](lib/routing/algorithms.ts) (1,611 lines), [actions/route-override.actions.ts](actions/route-override.actions.ts) (1,176), [components/facilities/route-setting/route-setting-client.tsx](components/facilities/route-setting/route-setting-client.tsx) (992), [lib/routing/osrm.ts](lib/routing/osrm.ts) (983), and [components/facilities/route-map.tsx](components/facilities/route-map.tsx) (891). Extract cohesive route-card, dialog, and service units without changing routing behavior in the same pass.
- **Low — add role-segment boundaries.** Only the root error/loading boundaries are present; add role-level `error.tsx` and `loading.tsx` to keep a failing dashboard widget from blanking an entire role shell.

## 2. System Design & Routing Logic

**Current state.** `side-selection.ts` and `manual-plan-training.ts` demonstrate useful pure logic. `corridor-core.ts` is also a synchronous, injected-data planner, but production code does not import it; runtime route generation still uses the duplicate async `planCorridorRoutes` in `algorithms.ts`. The latter combines database loading, geocoding, OSRM matrices/polylines, route decisions, time calculation, and persistence. Recent fixes made the duplicated growth-candidate skip behavior and Dhaka time calculations more consistent, but they do not resolve the architectural duplication.

### Where and How to Improve

- **High — finish the corridor-core migration safely.** Runtime currently calls the planner in [lib/routing/algorithms.ts](lib/routing/algorithms.ts); the pure alternative is [lib/routing/corridor-core.ts](lib/routing/corridor-core.ts). Add recorded golden fixtures that compare old and core outputs (vehicle assignment, stop order, errors, and tie behavior), design bounded candidate-leg prefetch that does not amplify public OSRM throttling, then wire the core and remove the duplicate implementation. Do not prefetch every possible pair blindly: the current cold public-server path can involve thousands of legs, spaced by the provider throttle.
- **High — resolve the OSRM-versus-trained-time policy.** `applyRouteCandidate` calculates pickup times from `candidate.legMinutes`, which come from route analysis/OSRM, while generation policy says new pickup times must use learned/finalized legs only. Decide whether a user-applied map candidate is an explicit exception; otherwise use the trained-leg timing core or make the exception visible and tested. Location: [actions/route-analysis.actions.ts](actions/route-analysis.actions.ts).
- **Medium — extract pure logic from orchestration.** Keep Prisma, `fetch`, and env access in shells; move retiming, route timing, label parsing, and learning aggregation out of [actions/route-override.actions.ts](actions/route-override.actions.ts), [actions/route-learning.actions.ts](actions/route-learning.actions.ts), and `algorithms.ts`. `route-override.actions.ts` also imports constants/helpers from the large `algorithms.ts` module, creating avoidable coupling.
- **Medium — test the actual route planner contract.** Current corridor tests exercise the new core, but there is no golden equivalence test proving the production planner and core produce the same route set. Add tests for capacity, ordering/ties, skipped infeasible candidates, OSRM fallback, and vehicle reuse before deleting either implementation.
- **Resolved since the prior report:** the production planner now has explicit UTC/Dhaka date conversion; learned-route training filters to finalized/executed plans, excludes the 20:00 `PRESET_10PM` placeholder leg, and swaps learning rows transactionally; route-growth feasibility skips a bad candidate instead of stopping the whole growth loop. Keep those regression tests.

## 3. Performance & Scalability

**Current state.** Positive changes include request timeouts/retries for OSRM and Nominatim, serialized public-server throttling, bounded/capped in-memory route/geocoder caches, bounded fixed-arrival/day concurrency, matrix coordinate deduplication/chunking, DB-side date filtering for allocation reports, and invalidation for the two current `unstable_cache` readers (`settings`, `vehicles`). The schema now has broad index coverage and the applied migration includes previously missing FK indexes. The remaining concerns are unbounded reads, post-cap in-memory search, sequential row loops, and the cold public-OSRM corridor sweep.

### Where and How to Improve

- **High — remove full-table user reads and in-memory filters.** [lib/queries/users.ts](lib/queries/users.ts) calls `findMany()` without `take`/cursor pagination, then filters `getAllUsers` and `getEmployeeDirectory` in memory. Push search into Prisma `where`, select only needed fields, and add stable pagination. The operations ad-hoc page also fetches every active employee for its employee picker without a limit: [app/operations/adhoc/page.tsx](app/operations/adhoc/page.tsx).
- **High — fix report search truncation.** [lib/queries/reports.ts](lib/queries/reports.ts) pushes date ranges into SQL, which fixes the old date-range bug, but `q` is applied after `take: MAX_UNFILTERED_ROWS`. Matching records beyond the cap are silently omitted. Push the text predicate into the query or paginate through all date-matched rows.
- **High — bound audit/approval queues.** [app/facilities/profile-approvals/page.tsx](app/facilities/profile-approvals/page.tsx) loads every historical request, and the new [lib/queries/audit.ts](lib/queries/audit.ts) fetches up to 500 matching users to build actor IDs. The 500-user cap makes actor searches incomplete for broad terms. Add date/status filters, database pagination, and an actor relation/denormalized searchable field strategy.
- **High — reduce serial allocation work.** [actions/route-assignment.actions.ts](actions/route-assignment.actions.ts) processes day-sheet rows sequentially; each weekly assignment performs day/vehicle lookups, an upsert, and a blocking email send. `copyLastWeekRoutes` also does per-day lookups and sequential writes. Preload maps, batch guarded writes, and dispatch emails through one bounded `after()` callback using the pooled transporter.
- **High — window route learning history.** [actions/route-learning.actions.ts](actions/route-learning.actions.ts) selects only required columns and filters route status, but still reads every finalized/executed plan and every manual-plan row and rebuilds the full aggregate on each mapping run. Add a documented retention/window or incremental cursor strategy, with a rebuild path for corrections.
- **Medium — reduce route payload size.** `getGeneratedRouteDetails` reads every route for the week and includes all scalar fields plus nested trip data; `routeAnalysis` JSON geometry is therefore included in every refresh. Use an explicit select and fetch analysis only for the open/selected route.
- **Medium — optimize the cold public-OSRM corridor path.** `planCorridorRoutes` awaits leg-geometry work serially in nested route/member/position sweeps. `prefetchRoutePolylines` is bounded for self-hosted OSRM but deliberately returns early for the public rate-limited server. Use cached/cheap spatial filtering and a bounded candidate-only prefetch plan; preserve the current public-host throttle.
- **Medium — expose per-cell matrix fallback.** Matrix requests are now deduplicated and chunked under the 100-coordinate cap, and complete table failures are surfaced by the planner. Individual unroutable table cells still fall back to straight-line distance inside `getDistanceMatrix` without a corresponding user-visible warning. Track and report those fallback pairs.
- **Low — review indexes with production stats, not guesswork.** `schema.prisma` has 79 index/unique declarations and the missing-FK index migration is applied. Review low-selectivity single-column indexes such as `isActive` and `EmailNotificationLog.status`, and case-insensitive searches on address/name/email that are not supported by ordinary btree indexes. Use `pg_stat_user_indexes` and query plans before dropping/adding indexes; do not drop the differently ordered route-plan composite indexes without evidence.
- **Resolved since the prior report:** the route-setting page no longer writes `Vehicle` rows while rendering; shared fleet/settings caches have matching invalidation; caches are capped; independent weekdays are concurrency-capped; matrix coordinates are chunked/deduplicated; and the report date predicate is SQL-side.

## 4. Security & Best Practices

**Current state.** Static scan found guards in 62 of 66 exported async Server Actions; the four without guards are public login/logout/reset-request/reset-submit flows. Guard calls are generally before the action `try` block. Error sanitization is centralized in `lib/actions/action-error.ts`, and the Prisma client globally omits password/reset fields. Reset tokens are hashed, 30-minute, atomically consumed, and rate-limited. Important exceptions and business-state flaws remain.

### Where and How to Improve

- **High — fix raw error leakage in assignment actions.** `assignRoute` returns `error.message` from its catch; the day-sheet catch also places `error.message` into a client-visible skipped-row reason. Prisma/network messages can expose schema or infrastructure details. Route both paths through `sanitizedActionError`/a safe domain-error mapper and keep raw errors only in server logs. Location: [actions/route-assignment.actions.ts](actions/route-assignment.actions.ts).
- **High — enforce assignment eligibility and non-overwrite rules server-side.** `upsertAssignmentForWeeklyDay` does not require `weeklySchedule.status === APPROVED` or `day.needsTransport`; ad-hoc assignment does not require an assignable status. `replicateAcrossWeek` upserts every transport day and overwrites existing allocations. Enforce state predicates in the database mutation and skip already allocated days atomically. These checks must cover normal assignment, day-sheet, replication, and copy actions.
- **High — reconcile Super Admin / Facilities permissions.** [proxy.ts](proxy.ts) permits Super Admin into Facilities, but [app/facilities/layout.tsx](app/facilities/layout.tsx) currently gates only Facilities; seven Facilities-facing actions in `facilities-profile.actions.ts` and `route-assignment.actions.ts` also allow only Facilities. Either consistently grant Super Admin as project instructions state, or remove the proxy/layout promise and hide unusable workflows. Centralize this policy to prevent drift.
- **High — preserve records on account removal.** [actions/user-management.actions.ts](actions/user-management.actions.ts) has a hard-delete flow that deletes weekly/ad-hoc/change-request/manual-plan history before deleting the user, despite a deactivation/`deletedAt` mechanism and a three-year retention objective. Prefer soft deletion/deactivation; if a legal purge is required, use an explicit audited retention process and avoid cascading business history.
- **High — complete atomic audit coverage.** `AuditLog` and `auditEntry` exist, but `audit()` swallows write failure after the mutation has committed. Many profile/approval/auth flows call `await audit()` separately; several route-assignment, route-generation, pickup-point, and finalize mutations have no `AuditLog` entry. Use `auditEntry(tx, ...)` inside the same transaction for every mutation, and test rollback/atomicity. `RoutePlanOverride` is not a substitute for a system-wide audit trail.
- **Medium — remove plaintext passwords from email.** Account creation and resend-credentials flows email temporary passwords in message body/HTML. `mustChangePassword` reduces duration but email remains a replayable credential channel. Prefer one-time set-password links; at minimum, short-lived credentials should not be retained or resent and delivery failure should not expose raw SMTP details.
- **Medium — do not place home coordinates in GET URLs.** The authenticated `/api/routing/route` endpoint accepts waypoint coordinates in a query-string parameter. Map requests contain employee pickup/home locations; URLs may be recorded in proxy/access logs and browser diagnostics. Use a validated POST body with same-origin/CSRF protections and consider log redaction.
- **Medium — rate limiter fails open and has no active pruning.** `consumeRateLimit` returns `true` when the database is unavailable, bypassing login/reset limits exactly during an outage; `pruneRateLimitBuckets()` has no caller/scheduler, so old bucket rows accumulate. Decide fail-open versus fail-closed by operation, monitor failures, and schedule bounded cleanup.
- **Medium — add runtime schemas to every mutation.** Several actions still trust TypeScript/FormData shapes, notably route assignment IDs/times/comments and multi-row day-sheet arrays. Add Zod schemas with bounded strings/arrays and valid `HH:mm`/identifier formats immediately after the guard. The route-geometry, pickup-point, auth, and password schemas are good existing examples.
- **Low — strengthen secrets and account emails.** `SESSION_SECRET` accepts 16 characters; enforce a high-entropy minimum (at least 32 random bytes/characters per deployment policy). Keep current JWT payload Zod validation, 7-day revocable DB session, reset-token hashing, credential-field omission, and enumeration-safe reset response.
- **Resolved since the prior report:** session/RBAC coverage is broadly present; reset host-header construction, plaintext reset-token storage, long reset TTL, password-hash serialization, timing oracle, public health error details, OSRM/Nominatim timeouts, and HTML escaping findings were addressed. The immediate employee address-change flow remains an explicit product decision (30-day lock + notifications), not an audit defect to change without approval.

## 5. Code Quality & Technical Debt

**Current state.** `strict: true` is enabled, and targeted scans found no `any`, `@ts-ignore`, or `@ts-expect-error` usage. Ten `as unknown as` casts remain, including nullable matrix placeholders, Prisma schedule-shape casts, JSON casts, and a React render cast. Six test files currently pass 27 cases, primarily pure helpers. Tooling is not green: current typecheck has five errors; ESLint has one error and two warnings.

### Where and How to Improve

- **P1 — restore the required gates.** `npx tsc --noEmit --incremental false` currently reports five errors: missing `resendRouteAssignmentEmail`/`ResendEmailState`, missing `updateFixedArrivalServiceAction`, missing `setAllPickupPointCoordinatesAction`, and the `employeeCode` prop mismatch at `components/facilities/user-info-table.tsx`. `npx eslint .` reports `react-hooks/set-state-in-effect` in `components/facilities/edit-employee-profile-dialog.tsx` and two unused parameters in `actions/route-assignment.actions.ts`. Fix the contracts and lint issue; `npm run verify` currently fails at its typecheck step.
- **P1 — add behavior tests around Server Actions and persistence.** Existing tests cover route-side selection, manual-plan training, corridor-core candidate skipping, matrix batching, Dhaka conversion, and route-analysis input schemas. Add tests for weekly assignment eligibility, replication non-overwrite, error sanitization, Facilities/Super Admin role policy, audit transaction rollback, credential session revocation, and route-analysis/trained-time policy. Keep Prisma-dependent tests isolated behind a test database or inject repositories.
- **Medium — finish query/result decomposition.** Avoid returning complete Prisma records/route-analysis JSON through server actions where a compact DTO will suffice. Move read functions into `lib/queries` and keep `actions/` mutation-focused.
- **Medium — add compiler and lint guardrails.** Consider `noUncheckedIndexedAccess`, `noUnusedLocals`, `noUnusedParameters`, `noImplicitReturns`, and `noFallthroughCasesInSwitch` after resolving baseline errors. Add import-boundary rules (Prisma forbidden in components; core modules forbidden from importing I/O), and warnings for excessive file/function size.
- **Medium — split large workflow modules.** Extract services/hooks/components from the oversized routing, route-setting, user-management, route-map, and route-override modules. Do not mix structural refactors with behavior changes to the production planner.
- **Low — finish dead-code and doc cleanup.** Eight formerly orphaned components are already staged for deletion, and previously reported uncalled action exports are absent. `corridor-core.ts` remains unused by production code. Active root docs such as [DATABASE.md](DATABASE.md) and [DATABASE_QUICK_REF.md](DATABASE_QUICK_REF.md) still describe SQLite/FastAPI/Alembic, conflicting with `CLAUDE.md`, `docs/ARCHITECTURE.md`, and the real Prisma/Postgres app. Update or archive them.
- **Low — build in CI.** [.github/workflows/verify.yml](.github/workflows/verify.yml) runs `npm run verify` but not `npm run build`; add a production build gate after the current TypeScript errors are fixed.

## Items Deliberately Not Re-flagged

- Prisma default omission prevents password hashes/reset token fields from leaking through nested relations.
- Password reset uses hashed tokens, 30-minute expiry, atomic consume, session revocation, and public base URLs not derived from `Host`.
- OSRM and Nominatim have request timeouts/retries; geocoder/polyline caches are capped; public OSRM requests are throttled.
- Distance matrices deduplicate coordinates and split into requests within provider coordinate bounds.
- The route-setting render-time vehicle write is gone; fleet reads use a shared query/cache; settings/fleet cache tags are invalidated.
- Report date filtering is pushed into Prisma; route-learning filters finalized/executed routes and performs an atomic replacement.
- The prior audit's proposed missing FK indexes are now present in schema/migrations; migration status reports up to date.
- Employee address changes remain immediate with a 30-day lock because this was explicitly chosen as product behavior.
